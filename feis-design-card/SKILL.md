# feis-design-card — 东方编辑刊物风卡片

把一篇文章变成一组可发布的卡片图：**AI 负责编辑拆卡，脚本负责像素级渲染**。

成品：一组 1080×1440（3:4）PNG，白底、得意黑大字、窄栏英文导航、留白驱动。

## 怎么触发这个技能

**最省事的用法：把文章丢过来 + 一句「出卡片」即可。** 例如：

```
把这篇文章做成卡片：《xxx.md》
给我出一套卡
用卡片技能拆这篇
按非叔卡片风格把这篇做成图卡
```

**自动触发**（不必说"卡片"两个字）：直接发一篇 Markdown / 文稿 / 长文链接，语境是"想发图文""要配图""想拆成几条内容"时，本技能会自动接。

**不会触发**：只是讨论排版、问卡片设计问题、让你改单张图的文字——那些走普通对话；要真出图必须明确落到"出一套卡"这件事上。

**要注意**：本技能一次产出一组**新卡**并渲成 PNG。若只是问"规则是什么/怎么改参数"，直接答，不必跑渲染。

## 工作流程（严格按序）

### 1. 读文章，定主线
通读全文，找出 3–6 个核心论点 + 1 句能被反复引用的判断。回答：**读者看完这组卡要记住什么？**

### 2. 拆卡（3–8 张）
- **卡 1 = 封面**：两行超大中文标题（其中一行局部反白）+ 一个超大拉丁词，底部一张**全出血**主图（不给图注）。主图**默认矩形**，要异形才给这张图写 `shape`（见「封面异形」）
- **中间卡 = 论点卡**：`🧩 #章节名` + 一行浅灰副题 + 5–6 段正文 + 1 张配图（图下配一行浅灰小字图注，**纯文字、无符号**）
- **副题按体裁判定写法**（见「章节副题：两种写法」）——文章在**讲步骤/流程**就写 `StepN 短句`；是**并列观点/感悟**就写 `短句`（不带序号）。**封面卡没有章节块，一律不写副题**
- 图标**一律不写**，脚本默认给 🧩（见「图标与步骤标记」）
- 正文口语化改写，短句、禁互联网黑话；不要把长句整段搬进卡片
- **正文与图注一律不许出现 `「」『』《》【】`、方括号、项目符号等装饰记号**（见下节「文案符号」）
- **不要给卡片加编号与年份**（`{ NO. 02 }`、`VOL. 53 — 2026`）。报头只留 logo + 四栏导航，越干净越好；这类装饰被非叔明确否掉过
- **底部留白 150px 以内**算舒服，超过 250px 就补一段正文或加一张图
- **尾卡 = 提示词卡**（非叔的 AIGC 内容**必备**）：整组最后附上**生成这些图用的提示词原文**，读者才看得懂图是怎么来的。全文约 1100 字，**一张卡装不下、要拆 2 张**（见「提示词卡」）

### 2.5 文案符号（**硬规则，被否过两次**）

非叔原话：「`「」` 这种符号去掉；图片下方如果想介绍图片，就直接浅灰色小字介绍即可，**不要加任何符号**」。

| | 规则 |
|---|---|
| **正文** | 不许出现 `「」`。要引用某句话就直接写，不加引号——`「内容越复杂，留白越要坚定。」这很像…` → `内容越复杂，留白越要坚定。这很像…` |
| **正文（列举）** | 原来用 `「A」「B」「C」` 并列的地方改用顿号：`换成如何判断一款好茶、如何读懂一份体检报告、如何看懂一个城市的早餐` |
| **图注** | **纯文字**，不加 `[ ]`、不加 `「」`、不加任何记号。它是**图片说明**，直接讲这张图是什么（如 `配料表，判断的第一道门槛`）——**不要写成排版点评**（如 `编号即层级，小字承载知识密度`） |
| **可保留** | 标点照常用（`，。、；：——`）；破折号 `——` 是标点不是装饰，保留 |

**验收**：`grep -c '「\|」' manifest.json` 必须为 `0`；HTML 里 `<figcaption>` 内不得有方括号。

### 3. 找图
- 从文章里解析 `![[名字.png]]` / `![](path)`，`![[…]]` 无路径时先用 `mdfind -name "名字"` 全盘定位，再找文章目录、`wiki/assets/images/`
- **必须写绝对路径**
- 排版倾向（**取景位比图本身更重要**）：
  - **先判断这张图是不是这一页的主要内容**——是（一条提示词对应一张图）→ 必须写 `"layout": "auto"`（或 `inline`/`side`），**图绝不裁**；不是（只是配图/氛围）→ 用默认 `stack`，整组图底落在同一水平线更整齐。详见「正文卡图文构图」
  - **封面** → 竖版或方版图 + `bleed: true`（全出血，可配 `pos` 定中心）。**封面裁切是允许的**——非叔定过
  - **文章开篇那张带标题的海报 = 封面图，必须放卡 1。** 不要因为「图上印着字、裁切会切到字」就把它挪去内页末卡——那是判断失当（2026-09-21 被否）。封面裁切本来就被允许，而把它放到最后等于封面没了。**卡片大标题与海报内标题可能重复**，这是素材本身的属性：交付时如实说明，别自己拿主意把标题删掉
  - **图中带字的图不要放到正文卡**：正文卡的图走 `inline` 通栏，一旦带标题/角标，缩窄或裁切都会咬到字。带字的图只适合封面（允许裁）或通栏完整展示
  - **正文卡** → **默认不写 `height`**：图会自动吃掉本卡正文之后的剩余空间，于是五张卡的**图底落在同一水平线**——这是整组「整齐」的关键。同时脚本给图容器加了「不超过图片自然高度」的上限，横长图不会被为凑高度而左右裁切、切掉画面里的字
  - 需要**固定取景窗口**时才写 `"height"`（写了就不再自适应），配 `"pos"` 定中心。3:4 竖图当正文卡配图时：窗口从图片上部开始（`pos` 6%–10%），保住「页眉 + 完整大标题 + 副题」，切断落在下方内容行间；`pos` 取中值会把大标题拦腰切断、取 70% 以上会露出上一屏半截字
  - **一组卡里不要混用「固定高」和「自适应」**，统一用默认最整齐
  - 横向出血 `bleed_x: true`：横图左右拉到画布边缘（版心撑满）。**慎用**——与正文的左右边距不再对齐，实测在正文卡上效果过满，已回退
- **正文段数 5–7 段**最舒服（每段一句话）。段数直接决定图能吃多少空间：**段数少→图变得又大又抢，段数多→图被压扁；段数不齐的卡片，图高必然不齐**
- 没有合适图就留白或纯文字卡，**不要硬配**

### 4. 写 manifest.json
完整字段说明见 `scripts/render.py` 顶部 docstring，实样例见 `examples/manifest.example.json`。

### 5. 渲染
```bash
python3 ~/.workbuddy/skills/feis-design-card/scripts/render.py <manifest.json>
```
- 截图后端是 **macOS 原生 WebKit**（`scripts/snap`，与 article-to-card 同款，零安装）
- **必须非沙盒执行**（Bash 加 `dangerouslyDisableSandbox: true`）：WKWebView 需要窗口服务与系统字体，沙盒内会挂起或出空白图
- **不要用 Chrome headless**：本机 Chrome 沙盒子进程全部起不来，已实测放弃；浏览器只用系统自带的 WebKit / Safari
- 输出 `card_NN.png` + `_html/card_NN.html` 到 `output_dir`

#### 复现验证：**只认像素，不认字节**（踩过坑）

想确认"这个包解压到别处能渲出同样的图"，**不要比对 PNG 文件字节数**。WebKit 截图结果会受系统色彩管理影响，**同一份 HTML、同一台机器、不同时间渲出的字节数可以差 2%**（本轮实测 `1860149` vs `1897567`，画面差异仅平均 4.84/255 的均匀色偏）。用字节数判"不一致"会误报，白白怀疑包坏了。

正确做法——像素级比对（容差 0，退出码 0 即完全一致）：
```bash
scripts/pixdiff a/card_01.png b/card_01.png
# 尺寸 1080x1440  不同像素 0 / 1555200  (0.0000%)  最大通道差 0
```

判据：
- **同一会话内连渲两次 → 必然 0 像素差**（已验证：渲染是确定的）
- 跨时间比对若出现**大量小差值（平均 2–5/255）** → 是色彩管理色偏，不是包的问题
- 若出现**局部大差值（最大通道差 > 50 且集中成块）** → 才是真的有内容不同（缺图、字体没加载、缺文件）

### 6. 目检（不可跳过）
用 Read 逐张看图，重点查：
- 标题 `hl` **必须是同行 `text` 的真实子串**，否则那一行不反白（脚本已加保护，会静默跳过而不是串行）
- **报头是否透气**：logo 贴左、导航贴右（`margin-left:auto`），中间一大片留白是刻意的；上边距 56px
- **导航有没有方括号**：`[ VISUAL STUDIES ]` 这种写法已被否——方括号没设计感、双词太长。只留**单个单词**，靠 `.22em` 字距撑开节奏。四栏词不重复、也不与报尾 `AIGC ARCHIVE` / `ART DIRECTION` 撞词
- **报头有没有多余的装饰**：`{ NO. 0N }`、`VOL. NN — 20XX` 这类编号/年份一律不该出现；报头只有 logo + 四栏导航
- **章节名离报头够不够远**（`.hd` margin-top 60px），报头变短后最容易在这里显挤
- **三档空隙是否分明**（层次感的命门）：标题→正文 **86px** ＞ 段↔段 **57px** ＞ 行↔行 **21px**，比例约 4:3:1。**只要标题后间距 ≤ 段间距，这张卡就没有层次**，必须检查首段有没有吃到 `.hd + .para` 的 72px。用 `scripts/rowprofile` 量成品，别凭肉眼
- 报头 logo 是否清晰可辨（太小就是一坨笔画）；报尾三栏是否居中且不与报头重复
- 全出血图**不得盖住报尾**（`bleed` 只做左右出血，纵向靠 `flex:1` 撑满 `.body`）
- **用了异形的封面，图内的字有没有被咬掉**：不确定就先用「不写 shape」渲一版对照。图内带字时只推荐 `tear`
- **正文是否够大**：30px 是现在的默认档（得意黑是窄体，同样 26px 排出来比苹方短一截、看着小气）。**导语→配图之间只该有 48px 上下**，量出来有 100px 出头就是有人用 `min_lines` 给短导语补了空行——补出来的空行正落在配图上方，读起来就是「图文间距过大」（2026-09-21 非叔在《华夏衣冠》卡 7 上就是这么发现的）
- **段距与行距的量级是否拉开**：行距 51px、段距 36px。段距若调到接近行距，段落就糊成一片
- **五张卡的图底是否落在同一水平线**：正文卡默认自适应，正常情况必然对齐；没对齐就说明有卡写了固定 `height`，或正文段数差距过大
- 配图是否被裁到看不出是什么
- **全组字号是否只有两档**（中文 30 / 英文 22）：把每张卡的 `<p class="para">` 字号列出来对一遍，出现 21/23/24/38 之类就是又按卡调了字号。查法：`grep -oh 'font-size:[0-9]*px' _html/card_*.html | sort -u`
- **配图是否与正文同宽**：量 `_html/card_*.html` 里的 `<div class="ph" style="width:…">`，**都应是 952**（= 版心宽）。出现 838 之类就是写了 `height`
- **各卡的图顶 y 是否一致**：`scripts/rowprofile` 量出来应全部相同（《华夏衣冠》30px 版实测全为 **458**）。参差说明有卡的导语折成了两行——**导语要压到一行内**（30px 下 ≤ 37 字），不要用 `min_lines` 补空行凑高度
- **原文开篇的封面图在不在卡 1**：带标题的海报被放到内页末卡是错（被否过）。封面卡裁切允许，别为躲裁切把图挪走
- **配图有没有「切字」**：横切断口不许落在一行中文的腰上（半截笔画最像 bug）。竖图取景必须让大标题完整、切断落在内容行间；出现半截字就调 `pos`
- 正文卡是否都排到 5 段以上（段数太少 → 图会被撑得过大过抢）
- **图标是否整组一致**：所有带 `#章节名` 的卡，图标必须都是 🧩，不许一张 💡 一张 🧩
- **副题有没有用错体裁**：文章讲步骤/流程 → 该是 `StepN 短句`，且 `N` 从 1 起跨卡累加（不按卡号算、不每张重置）；文章是并列观点 → 该是**不带序号**的裸短句。**两种写法不许在同一组里混用**，一张 StepN 一张裸短句 = 结构断裂
- **副题里有没有 `*`**：`*` 已废弃（非叔原话「不要这玩意」）。写法就是 `Step1 留白要坚定`，序号与短句之间**一个空格**
- **报尾中栏是否为 `Copyright © 2026 ｜ 非叔Design`**：`©` 不能丢；两段必须**同色**，只靠字重区分；整条报尾是深墨 `#1A1A1A`，**出现浅灰就是退回了被否的旧写法**
- **正文里有没有 `「」`**：硬查 `grep -c '「\|」' manifest.json` 必须为 `0`。要引用就直接写、并列就改用顿号；`「中式模板」` 这种括号被非叔明确否掉过
- **图注有没有符号**：`<figcaption>` 内不许有 `[ ]`；且内容必须是**图片说明**而非排版点评

### 7. 交付
`present_files` 一次性交付全部 PNG，按卡号顺序。

## 视觉基因（源提示词）

**本技能的版式不是凭空设计的，是从下面这条「东方编辑美学」通用提示词反推出来的。** 它此前只存在于对话里、从没进过技能，2026-09-17 补录入库。

**它有两个用途：**

1. **换主题时只改末尾四行**（主题 / 用途 / 张数 / 比例），得到的就是一整套新的图像方案——可用于 PPT 页、报告首页、文化海报、信息图。
2. **卡片缺配图时**：拿它去图像生成平台先出一组 3:4 底图，再喂给本技能排版。

**分工必须分清**：这条提示词负责**生出图**（AI 绘画），本技能负责**把文字排成卡**（HTML + WebKit 渲染）。两者是上下游，不是替代关系。

**提示词 ≠ 卡片约束**（非叔 2026-09-18 明确：「这是提示词，而不是卡片的约束」）。提示词里的**水印、张数（不低于 10 张）、比例**等要求，只作用于**生成出来的图**；卡片不继承这些，卡片只服从本文件的规格。**别把提示词的内容误当成卡片的待办项。**

```
请生成一种东方编辑美学的视觉方案：画面像铺在温润纸面上的一页克制刊物，整体安静、留白充足，却被少量高压的文字与色块牢牢钉住。不要把参考对象理解成固定题材，而要提取它的工作方式：用极大的汉字、数字或关键符号作为空间骨架，让它们可以被画面边缘裁切，只露出局部笔画、弧线、竖线和横线，像建筑结构一样支撑版面；再用极小的正文、英文注音、日期、标签、脚注或数据说明形成细密而有呼吸的阅读层级。标题不必完整陈列，可以成为画面里的形状、边界和节奏，正文则保持清瘦、疏朗、字距微开，像被认真排过的博物馆说明牌。

色彩系统以大面积低饱和浅底承载空气感，可以是米白、宣纸灰、淡粉、冷白或轻暖灰，具体温度根据内容气质调整；主内容颜色保持沉稳克制，用墨灰、炭黑、深褐、深青或低明度主题色承担信息重量；强调色只占小到中等面积，继承参考图那种“朱印式”的权威感和节奏感，但不要机械固定为红色。若内容偏学术，强调色可以变得更冷、更干净，像深蓝或铁灰中的细线；若内容偏节庆、文化、食物或手作，可以更温热、更颗粒化，像朱砂、陶土、枣红或熟橘；若内容偏科技、金融或医疗，则让强调色变得锋利、低饱和、面积更小，承担定位、警示或关键数据的职责。无论颜色如何变化，都保持原图的关系：浅底是空气，深色是文字秩序，强调色是情绪转折，灰色纹理是时间感与深度。
```

## 空隙层级（层次感全靠它，**必须三级分明**）

卡片是"一屏一文"，读者靠**空隙量级**判断内容结构。三档空隙一旦相等，标题就被吸进正文块，整页只剩一串等距的句子——非叔对这一点极敏感（原话：「正文和标题之间的空隙肯定不能和正文每一行之间的空隙相同啊，这样没有层次感」）。

| 层级 | 含义 | CSS | 实测视觉空隙 |
|---|---|---|---|
| **标题 ↔ 正文首段** | 章节开场 | `.hd + .para,.sub + .para{margin-top:72px}` | **86px** |
| **段 ↔ 段** | 换意 | `.para{margin-top:36px}` | **57px** |
| **行 ↔ 行** | 连续阅读 | `line-height:1.7`（51px 行盒 − 30px 字形） | **21px** |

比例约 **4 : 3 : 1**。三条硬规则：

1. **正文首段不许沿用 `margin-top:36px` 的段距**。早期写法里首段和其他段同用 `.para` 的 36px，结果标题→正文 49px、段间 54px——**标题间距反而比段间距还小**，层级完全倒置。已用 `.hd + .para` / `.sub + .para` 相邻兄弟选择器单独提上去。
2. **配图前的空隙（48px → 视觉 60px）允许与段距接近**。图是照片块，靠"形"与文字块区分，不靠"距"；再往上加会让横长图被迫上下裁切、可能切到画面里的内容，得不偿失。
3. **导语与配图之间不许出现"隐形的一行"**。段末补出来的空行正落在配图上方，视觉上就是 100px 出头的空档——最像"间距没调好"的一种错（2026-09-21 非叔原话：「这个图片和上面的文字的距离有多过于大了吧」）。**导语一律压进一行**（30px 下 ≤ 37 字），不要靠 `min_lines` 补空行；真要两行就整组都写两行。

**验证方法**：`scripts/rowprofile <card.png> [阈值] [最少墨点数]`——行剖面工具，扫描成品 PNG，把"有墨的行"合并成块并输出每块的 y 区间与块间距，直接读出三档空隙的真实像素。数字对不上就是 CSS 没生效。

配套的 `scripts/colprofile <card.png> [y0] [y1] [阈值]` 是**列剖面**：量指定 y 区间内墨迹的横向范围（最左/最右 x、实占宽度、分段）。判断"这行还能不能再大一号""导语会不会折行"就靠它——不用猜字宽。

配套的 `scripts/gap [编号…]` 是**顶隙/底隙**：在卡片输出目录内运行，输出每张卡的顶隙（页眉→标题）、底隙（正文底→页脚）与差值。`valign:"fixed"` 的验收标准：**顶隙全组必须相等**（差 ≤2px 是字形行盒，肉眼为 0），底隙收在顶隙 ±60px 内；底隙不合格就调内容行数，不要动 top_gap。

```bash
~/.workbuddy/skills/feis-design-card/scripts/rowprofile card_02.png 235 6
~/.workbuddy/skills/feis-design-card/scripts/colprofile card_02.png 355 390   # 量导语那行占多宽
~/.workbuddy/skills/feis-design-card/scripts/gap                              # 量全组顶隙/底隙
```

## 图标与步骤标记

### 章节图标 = 🧩，固定，不随文章变
图标**不是内容**，是版式记号——它标记「这里是章节起始」，跟文章主题无关。所以：

- **整组卡永远用同一个图标**，脚本里 `DEFAULT_ICON = "🧩"`，manifest 里**不要写 `icon` 字段**
- 一旦让图标跟着文章走（讲效率用 ⚡、讲灵感用 💡），同组卡片就会出现两种符号，视觉体系立刻散
- 只有「整组卡换一套主题符号」才改 `DEFAULT_ICON`，改完这一组全部统一
- 图标本身是彩色 emoji，是全卡唯一的彩色点。要它跟黑白版式更融，可给 `.ic` 加 `filter:grayscale(1)`；**默认保留原色**

### 章节副题：按体裁二选一（流程型 / 观点型）
`subtitle` 位（34px 灰字，`#章节名` 下面那行）承载这行副题。**先判断文章体裁，再决定写法**：

| 文章体裁 | 写法 | 例 |
|---|---|---|
| **讲步骤 / 流程 / 方法**（「第一步…第二步…」「先…再…」） | `StepN 短句` | `Step1 先看配料表` |
| **并列观点 / 感悟 / 现象分析**（几个互不从属的论点） | `短句`（**不带序号**） | `先讲清画面怎么工作` |

**判断依据是原文本身，不是「有没有『先』字」**——像「先看哪儿，再看哪儿」讲的是读者的阅读动线、不是操作序列，不构成步骤型。

- **不写 `*`**：`*` 号已废弃（非叔原话「不要这玩意，对画面美没帮助」）。序号与短句之间**就是一个空格**
- **两种写法视觉完全一致**：都是 34px / 400 / `#A3A3A3` 浅灰小字，层级与点缀感无差别，区别只在**语义**
- `StepN` 的三条硬约束：
  1. `N` 是**整组全局连续序号**，从 1 开始跨卡累加（论点卡之一 = Step1、之二 = Step2…），**不按卡号算、不每张重置**
  2. **同组要么都写 `StepN`、要么都不写**；一张有一张无 = 结构断裂
  3. 短句 4–8 字、带态度（`留白要坚定`、`先讲清画面`），**不要写「第一步：准备素材」这种流水账**
- **封面卡不写副题**（无章节块）
- **2026-09-15 两次修订留痕**：先由「仅流程型」放开为「观点卡也挂 StepN」（非叔选 B）；当日非叔回调定稿——**「涉及按步骤分析的文章就用 B，不涉及就用 A」**，即由体裁决定写法，不再一刀切

## 提示词卡（尾卡，**AIGC 内容必备**）

**为什么要有**：非叔做的是 AIGC 教程，读者来看的就是「这套图是怎么生成的」。卡片只给成品、不给提示词，读者看完不知道他在做什么——所以**每组 AIGC 主题的卡，结尾都要附上生图提示词原文**。

### 规格

| 项 | 值 |
|---|---|
| 位置 | 整组最后，接在 `#非叔说` 之后 |
| 数量 | **2 张**（全文约 1100 字，一张装不下，见下） |
| 章节名 | `🧩 #提示词`（两张同名，同组一致） |
| 副题 | 按提示词的段落结构起，帮读者看懂骨架。例：`骨架、色彩与空气感` / `版式、文字与本次参数` |
| 正文 | **原文照登——不改写、不精简、不总结**。读者要能直接复制去用 |
| 配图 | **不配**。纯文字，气质是刊物的「创作说明」 |
| 变量槽 | 末尾的主题／用途／张数／比例**一起登**，它交代了这组图的实际参数 |

### 为什么必须拆 2 张（实测数据）

30px 正文在 1080×1440 上，扣掉报头、章节块、段距后**一卡最多约 640 字**。一条完整提示词约 1155 字：

- **降到更小字号硬塞一张 → 实测溢出**（`para_size:20` 试过，末段被报尾压住），而且手机根本读不清 → **排除**
- **拆 2 张、字号跟全组一致 → 干净**，不破坏整组观感 → **采用**

拆法按提示词的自然段走：一张放「骨架 + 色彩」，一张放「版式 + 文字 + 本次参数」。

### 拆完还是贴报尾？只收行高，不动字号

30px 下两张提示词卡的余量会变小（《好醋判定》实测卡 7 的末行到 y=1372，报尾文字在 1385，只剩 13px）。
这时给这两张卡加 **`"para_lead": 1.55`**（`para_size` 保持默认 30）——行距从 51px 收到 46.5px，
末行立刻回到 y=1285，报尾上方留出 99px。**字号一档都不能动**，收紧行距是长文附录唯一允许的例外。

### `para_size` / `para_lead`（长文附录专用，**慎用**）

卡级覆盖正文字号与行高（默认 **30 / 1.7**）。**常规论点卡一律不写**——30px 是默认档，调小就是画面发散、手机上读不清。提示词卡也**优先靠拆卡 + 收行高解决，不要靠缩字号硬塞**。

## 正文卡图文构图（`layout`，**图不能被裁时必用**）

`layout` 不写 = **`stack`**（老行为：图在正文下方通栏，**会为凑高度而裁**）。
但当**图就是这一页的主要内容**（一条提示词对应一张图）时，裁图＝丢内容——这时必须换版式：

| `layout` | 构图 | 图怎么放 | 裁不裁 |
|---|---|---|---|
| 不写 / `stack` | 纵向堆叠 | 正文之后通栏，吃剩余空间 | **会裁**（封面出血同理，封面允许） |
| `inline` | **嵌入式** | 插在第 `image_at` 段之后；宽图通栏，过高的图限高居中 | **绝不裁** |
| `side` | **左右构图** | 图占一侧整栏、正文在另一侧，两栏垂直居中 | **绝不裁** |
| `auto` | 自动选 | 按首图比例：**竖图(<0.95)→`side`，其余→`inline`** | **绝不裁** |

**`auto` 必须显式写**（`"layout": "auto"`）。默认保持 `stack` 是硬要求：否则已交付的老卡会被判成新版式、逐像素全变。踩过这个坑——没守默认时《好醋判定》5 张全被改成 `inline`，平均差 57–103/255。

### 不裁是怎么做到的
把容器宽高比做成**和图片一模一样**（尺寸由 `render.py` 按 canvas/pad 折算成绝对像素写进 inline style），`object-fit:cover` 就退化成「刚好铺满」，一个像素都不切。

- **刻意不用 `aspect-ratio` + `height:100%` 这类百分比链**——WebKit 在 flex 里会塌，折算成绝对像素才可复现
- `height` 字段在 `inline`/`side` 下**语义变成「限高上限」**：图矮于上限就通栏，高于上限就缩到上限并居中，两种情况都不裁

### 实测取景尺寸（1080×1440，版心 952）
| 原图比例 | `inline`（限高上限 60% 可用高） | `side`（默认 `side_w` 0.62 / `side_fill` 0.92） |
|---|---|---|
| 16:9（1.78） | **952×534 通栏** | 457×256（太矮，横图别用 side） |
| 2.34（横幅） | **952×407 通栏** | — |
| 1:1 | 644×644 限高居中 | 590×590 |
| 3:4（0.75） | 483×644 限高居中 | **590×787** |

**⚠ 铁律：`inline` 模式默认别写 `height`。** 写了上限，横图就会被缩窄成「上限 × 比例」——
实测版心 952 配 `height:470` 的 16:9 图，**图宽只有 838**，比正文窄一截、还居中缩进，
整组卡图文都不对齐（2026-09-21 非叔直接点出：「图片和提示词都不一样宽」）。
**不写 `height` 才通栏 = 与正文同宽**：《华夏衣冠》重做后 7 张图全部与正文同宽 **952**，
图顶统一落在 **y=458**（30px 正文 + 单行导语版），分毫不差。要一张窄图时才写 `height`。

### `side` 的两个旋钮
- `side_w`（默认 **0.62**）：图占版心宽的比例上限
- `side_fill`（默认 **0.92**）：图高占可用高度的比例上限
- `side`: `"left"`（默认）/ `"right"`
- 两个默认值是量出来的：图占满可用高度大半、上下只留约 150px 呼吸，同时文字栏还剩约 318px（30px 中文约 9 字/行）仍读得下去。**想让图更大就调 `side_w`，代价是文字栏跟着变窄**

### 段落级样式 & **全组字号只有两档**（2026-09-21 定，硬规则）
`paras` 每段可以是字符串（常规段），也可以是 dict 单独覆盖**这一段**：

```json
"paras": [
  "曲裾深衣，衣襟绕体而行，行不露足，是汉代礼制与端严之美的源头。",
  { "text": "A solemn and refined adult Chinese Han noblewoman, ... --s 250",
    "size": 22, "lead": 1.55, "color": "#3A3A3A" }
]
```

| 栏位 | 字体 | 字号 | 墨色 | 怎么写 |
|---|---|---|---|---|
| **中文叙述**（导语 / 说明 / 注解） | 得意黑 | **30px** 行高 1.7 | `#1D1D1D` | 不写 `size`（走默认） |
| **英文提示词 / 参数** | 得意黑 | **22px** 行高 1.55 | `#3A3A3A` | 每段都写 `"size":22,"lead":1.55,"color":"#3A3A3A"` |

- **正文与标题同一套字（得意黑）**——`.para` / `.list .k` / `.list .v` / `.sub` / `figcaption` / `.quote .by`
  全部 `font-family:'Disp'`，只有报头导航与报尾拉丁小字留系统字
- ⚠ **换字体会改变行数**：得意黑比 PingFang 略宽略高，同一段文案的折行数会变，**stack 模式的配图高度
  也跟着变**。每次动字体后必须用 `rowprofile` 复核每一张卡的**末行有没有顶穿报尾**（footer 文字约在
  y=1385，末块底超过 1369 就是已经压上去了）
- **得意黑只有一个字重**：`font-weight:600` 会被合成加粗、笔画糊成一块。凡是原来写 600 的位（章节副题、
  清单标签、金句出处）一律改 **400**，层级靠颜色深浅分，不靠字重

- **同一档在全组所有卡上用同一个数**。不许"这张字多缩到 21、那张字少放到 23"——那是草稿感的最大来源。长文请改拆卡，不要动字号。**渲染器会自检**：某段字号既不是 30 也不是 22（且不等于本卡 `para_size`）就打印 `WARN: 一段的字号是 24px —— 全组只允许 30px/22px 两档`
- **30/22 是量出来的**：得意黑 1 全角字实占 0.79em，版心 952px 在 30px 下正好放 40 字——导语写 32–37 字既填满又不折行；英文档 22px 下每行 103 字符，最长 917 字的提示词排 9 行，配 952×534 的图正好一屏
- `min_lines: N` = 给这一段撑起 N 行的高度。**只在整组导语确实都是 N 行时用**；拿它给一行写完的导语补空行，补出来的空档正落在配图上方，读起来就是「图文间距过大」（2026-09-21 被非叔当场指出）。**正确做法是把导语压进一行**，不是补空行。渲染器会自检并打印 WARN
- **没有覆盖时不写 `style` 属性**——老卡的 DOM 与 CSS 一字不差，保证像素级回归

### 无配图的卡：用 `list` 条目 / `quote` 金句把版面撑满

同一套卡里若有条目**原文就没配图**，别硬找图；也**绝不许按这一页反推字号去填**
（2026-09-21 非叔否掉：「有的 card 里正文字体大小都不统一」——正是每卡反推字号造成的：
全组出现 21/22/23/24/38 五种正文大小，整组看着像草稿）。

**但更不能拿一个没有含义的大字去"占位"。** 2026-09-21 非叔看完成品原话：
「card10 和 card8 不能因为没图片就不写了啊，这样看着好看吗你觉得？」——幽灵大字会在页面
中央留出一大块灰白空洞，读者只看到「这页没写完」。**无图卡的规则是：文章少了图，
内容不能少——用文章自己的信息把版面撑满。**

两个替身块，可单用也可并用，顺序固定 `list` → `quote`：

**① `list` 条目清单（首选）** —— 细线分隔的参数／要点行，行高可被撑开吸收剩余空间，
于是整页从章节名一路排到报尾，中途不留空洞。

```json
{ "no": "08", "heading": "#圆领袍官员", "subtitle": "唐制 · 含元殿早朝",
  "layout": "inline", "image_at": 1,
  "paras": [ "唐代圆领袍、幞头、革带与鱼袋俱全，是衣冠治国、盛世礼序的象征。",
             { "text": "A dignified adult Chinese Tang official, …… --s 250",
               "size": 22, "lead": 1.55, "color": "#3A3A3A" } ],
  "list": [ { "k": "形制", "v": "圆领袍 · 幞头 · 革带 · 鱼袋" },
            { "k": "场景", "v": "含元殿丹陛 · 铜鹤 · 云纹幡" },
            { "k": "光线", "v": "冷调晨光压暖色宫灯" },
            { "k": "气质", "v": "端严 · 清贵 · 盛世礼序" } ] }
```

- 每行两种写法：`"纯文字行"` 或 `{"k":"标签","v":"内容"}`
- 样式：上下各一条 `#E6E6E6` 细线；标签 **17px/400/`#A3A3A3`/字距 .14em**（`min-width:132px`），
  内容 **30px/1.6/`#1D1D1D`**（直接借中文正文档，**不另开字号**）
- **条目 3–6 条**：少于 3 条撑不满（每行最高 200px，再高也填不上）；多于 6 条会被压回自然行高
- **清单顶边 48px，与同组配图的顶边齐平**（实测《华夏衣冠》都在 y=458）——整组翻下来，
  「有图的」和「没图的」内容起始线落在同一条水平线上
- **条目必须是文章自己的信息**（形制／场景／光线／比例／负面词），不许为填空编凑

**② `quote` 金句块** —— 把原文里最有态度的一句放到配图本该在的位置，用超大字撑起版面。
和幽灵大字的区别在于：**这里放的是文章自己的话，读者读得懂，大字因此是内容、不是占位符。**

```json
"quote": { "text": "衣冠治国\n盛世礼序", "size": 72, "by": "唐制 · 圆领袍" }
```

- 默认 68px 得意黑 / `#0D0D0D`；`\n` 手动断行；`by` 是出处小字（17px/400/`#A3A3A3`）
- **文字必须摘自原文**，不许自造口号
- 与 `list` 并用时排在 `list` 之后

**渲染器自检**：无图卡若既没有 `list`／`quote`，脚本会用 `est_content_bottom()` 粗估正文排完
落在哪个 y（按得意黑实测的 CJK 0.79em／拉丁 0.42em 折算，与 `rowprofile` 实测只差十几像素），
**底部还空 400px 以上**就打印 `WARN: 无配图的卡正文排完后底部还空着约 Npx`——看到这句就回去补内容，别硬渲。
（阈值校准过：好醋判定那两张长提示词卡底部空 100–300px，属正常留白，不报警。）

`giant` 字段保留但**不再推荐**（仅为兼容旧 manifest），新卡一律走 `list` / `quote`。

## 封面异形（manifest 开关，**默认矩形**）

封面主图**默认矩形填充**，不要主动做成异形。非叔的定调：**预设矩形，他说要变体时再换。**

要变体时，在封面卡的配图上加一个 `shape` 字段即可——**不用改脚本、不用手改 CSS**：

```json
"images": [
  { "path": "…/cover.png", "bleed": true, "pos": "center 42%", "shape": "tear" }
]
```

| `shape` | 形状 | 实现 | 归档示例 |
|---|---|---|---|
| 不写 / `none` | **矩形**（默认） | — | `…/shape_1_rect.png` |
| `diagonal` | 斜切——上缘左高右低 | `clip-path:polygon(0 0,100% 13%,100% 100%,0 100%)` | `…/shape_2_diagonal.png` |
| `moongate` | 月洞门——椭圆拱顶 | `border-radius:50% 50% 0 0 / 30% 30% 0 0` | `…/shape_3_moongate.png` |
| `tear` | 撕纸边——不规则手撕上缘 | 89 点多边形，浅裂 70% / 中裂 22% / 深撕口 8%，seed 固定可复现 | `…/shape_4_tear.png` |

归档图在 `小绿书/卡片输出/封面异形示例/`（上表以 `…/` 省略该前缀）——`shape_1..4_*.png` 是**当前规格**的四连实测图；`cover_A/B/C_*.png` 是早期手改 CSS 的旧版（页脚还是浅灰），只作历史参考，不要照它调色。

形状只换主图轮廓，出血逻辑不变（左右仍靠 figure 的负 `margin`，底部照样压在报尾上方）。写了 `shape` 的那张卡，轮廓由 inline style 生效，会覆盖 `.ph` 的默认圆角。

**调参**（`render.py` 顶部常量，改一次全组卡生效）：
- `DIAGONAL_CUT`（默认 `13.0`）— 斜切右端下移的百分比，越小越平缓
- `TEAR_SEED / TEAR_POINTS / TEAR_DEPTH`（`17 / 86 / 8.0`）— 撕边种子、点数、最大深度

### 硬教训：异形会咬掉**图内**的文字

2026-09-15 用一张真实封面海报实测四形状（同一张卡，唯一变量 `shape`）：

| shape | 实测结果 |
|---|---|
| `none` | ✅ 图内文字全完整 |
| `tear` | ✅ **最可用**——撕边只吃最上一小条，且「撕」的语义让零星损失显得自然，不像事故 |
| `diagonal` | ⚠ 削掉右上 `PROMPT ANALYSIS` 的后半 + 右侧竖排小字顶部。切面太平整，**缺半个字很刺眼** |
| `moongate` | ❌ 拱顶直接削掉左上角一个字（「不是把」的「不」），最严重 |

→ **判据不是「异形好不好看」，而是「图上有没有字」**：
- **纯摄影 / 纹理 / 人像** → 三种随便用
- **图内带字**（海报、排版图、AI 生成的带字封面）→ 只推荐 `tear`；`diagonal` 需先把 `DIAGONAL_CUT` 调到 5–8 再试；`moongate` 直接排除
- 斜切方向**固定左高右低**：早期做成左低右高会切掉左侧标题首字，已翻面修正

  `/Users/macbook/Movies/JianyingPro/User Data/Cache/effect/7399865900821647935/5219d1f012f4944aaaa2ec19556fdea6/得意黑.ttf`（v2.0.1）。剪映缓存被清掉时，改从 `~/Movies/JianyingPro/User Data/Cache/AITextTemplate/Resource/*/SmileySans-Oblique.ttf` 找
- 截图走系统 WebKit；`snap` 缺失时脚本自动 `swiftc` 现编（首次 30–60 秒）
- 目检工具都是零安装的 Swift 单文件，源码就在 `scripts/`：`rowprofile.swift`（行剖面）、
  `colprofile.swift`（列剖面）、`pixdiff.swift`（像素比对）。二进制跑不了就现编：
  `swiftc -O scripts/colprofile.swift -o scripts/colprofile`
- 文件名与目录由调用方在 manifest 里指定，不要擅自改名
- 每次渲染后必须目检再交付，不许盲交
- **AIGC 主题的卡组必须带「提示词卡」**（见「提示词卡」）——只给成品、不给提示词，读者看不懂这组图是怎么来的
- **图是这一页的主要内容时（一条提示词对应一张图），必须写 `"layout":"auto"` 或 `inline`/`side`**——默认 `stack` 会裁图，等于丢内容。反过来，只是氛围配图就用默认，别乱开新版式
- **默认必须保持 `stack`**：绝不能把「不写 `layout`」当成 `auto`。老 manifest 不带这个字段，一旦默认变自动，已交付的卡会逐像素全变（踩过：好醋判定 5 张平均差 57–103/255）
- **组级写 `"valign":"fixed"` 时，封面卡要单独写 `"valign":"top"`**：fixed 会把出血图钉成自然高，封面底部空出约 260px 白（2026-09-29 实测）；交付前用 `scripts/gap` 看封面底隙，正常应贴到报尾（约 20px）
- **输出目录里的 `_html/` 是可微调的中间件，保留**
- **全组字号只有两档，不许按卡微调**：中文叙述 30px、英文提示词/参数 22px（副题 34px 是固定的版式位，不算第三档）。同一档在全组用同一个数。「字数多的卡缩一点、字数少的放大一点」= 草稿感（2026-09-21 被否）
- **导语一律一行写完**（30px 下 ≤ 37 字，用 `colprofile` 量）：全组导语行数一致，配图顶边才会齐。**不许用 `min_lines` 给短导语补空行**——补出来的空档就贴在配图上沿，读起来正是「图与文字间距过大」（2026-09-21 被非叔当场指出，原话：「这个图片和上面的文字的距离有多过于大了吧，这间距都调整不好啊？」）
- **正文与标题同一套字（得意黑）**：`.para` / `.list .k` / `.list .v` / `.sub` / `figcaption` / `.quote .by` 全部 `font-family:'Disp'`；只有报头导航与报尾的拉丁小字留系统字。**得意黑只有一个字重，600 一律写 400**（合成加粗会糊）。动字体后必须 `rowprofile` 复核每张卡的末行**没有顶穿报尾**（末块底 ≤ 1369）——换字体改折行数，连 stack 模式的配图高度都会跟着变
- **正文卡的图必须与文字栏同宽**：`layout: inline` 时**不写 `height`**，图才会通栏（952 = 版心宽）。写了 `height` 图会被缩窄到「height × 比例」，比正文窄一截
- **原文开篇那张「封面图」必须放卡 1**（封面位），不许因为「图上带字不好裁」就挪去内页——封面裁切是允许的，挪走才是错的（2026-09-21 被否：海报被放到末卡）
- **无配图的卡用 `list` 条目 / `quote` 金句把版面撑满**，不许放大正文字号填空，也不许再用没有含义的幽灵大字占位（2026-09-21 被否：「不能因为没图片就不写了」）。约 3 段以上正文、3–6 条 `list` 条目是一页的合适量
- **清单块与配图同一起始线**：`.para + .list{margin-top:48px}`，与 `.para + .figure` 的 48px 一致 → 无图卡的清单顶边正好落在同组配图顶边（实测 y=458）
